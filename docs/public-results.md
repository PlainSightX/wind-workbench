## 查询规划微调

结果助手的规划步骤（问题＋证据→操作计划）单独做 LoRA 对照：按原子义务组合程序化生成 800 条监督，
每条经真实执行器自检，微调 Qwen3-8B。300 题留出测试上首答通过率 77.3%，同口径 DeepSeek-Flash 41.3%、
Qwen3-32B 33.7%；此前写好的组合开发集上 29/32。测试与训练同一生成器，开发集更独立但只有 32 题；
旧问法面板与此前 32B LoRA 持平；只测首答规划，没有接入服务。见 [查询规划微调](results/sft-obligation-8b-20261017/README.md)。

## 预测方法

**ENGIE 四机组。** 420,480 行质量审查后，以持续性、Ridge 和 LightGBM 滚动比较。把 LightGBM 的训练目标
改为 L1、再向持续性收缩后，2014 三个开发季度的等季度 MAE 改善 1.80%，未达到预设的 3% 采用门，
默认保留持续性。冻结方案后对 2015 年做一次最终评价：MAE 改善 2.985%、RMSE 改善 4.038%，四个季度均改善。
2015 年数据现已用过，不能再当新方案的盲测。见 [开发对照](results/wind-engie-a2-20260923/README.md) 与
[最终评价](results/wind-engie-a3-20260923/README.md)。51,072 个可评分起报彼此相邻相关，不是 51,072 个独立样本。

**Q1 单序列。** 事前时间切分下，Ridge 正式留出 3,885 行 MAE 由 197.534 降到 183.187（−7.26%），
RMSE −9.22%。小型 Transformer 完成训练与模型交付，但没有胜出；低变化组 Ridge 仍落后于持续性。
见 [Q1 比较](WIND-SEQUENCE-RESULTS.md)。

这些是同一历史场景的离线对照，不代表跨场站泛化或客户收益。

## 实验服务与模型交付

任务登记、outbox、租约与执行批次校验防止投递和 worker 故障造成错误完成；模型包版本进入历史回放。
在全新空卷实例上完成真实 Q1 实验和选版预测；原 ENGIE 五个模型各 51,200 个合法输入在 CPU 回放，
与原预测最大差约 4.55e-13 kW，另有 15 个 HTTP 窗口核对发布、幂等和重启后读回。
见 [复现核验记录](public-verification.md)。

有限负载测试中，1,080 次核心请求有 932 次正确接受、148 次因预测容量被拒绝，没有非预期错误或数值错误；
这是单 worker、Linux CPU 下按端点分别请求的结果，容量拒绝是设计边界，不算成功。

Chronos-2 完成两个 seed 的真实训练，并在提交步边界完整恢复；独立环境重放 120,186 个开发窗口与原评分一致。
provider 总截止时间把一个本会生成约 37 秒的请求改为约 2 秒终止；这是可靠性，不是正常回答提速。
时序配方未满足默认采用条件；推理合并、编译与 FP8 都没有采用，保留 BF16/eager。

## 结果助手

结果助手把模型的选择与可信执行分开：模型选择查询操作和引用，程序执行数值、时间与阶段计算并校验。
默认关键词检索在 24 道开发题上为 24/24，向量 23/24，完整上下文 22/24；这些是反复开发用题，不是开放问答准确率。
曾出现“事实列表正确、正文没有回答阶段问题”，之后补了阶段正文校验，并用原问题和固定变体复核。

新服务实例上，四题真实 HTTP 确认批次的正文与引文逐份复核通过；此前同一问题曾在一次修复后因数字未绑定而拒答，
这个首次负结果保留，不声称首次 4/4。见 [复现核验记录](public-verification.md) 与 [助手困难案例](public-assistant-case.md)。

## 可选推理服务

同一 Qwen3-14B、六个已见问题做三轮「提示布局 × 前缀缓存」四格对照，72 项正式任务都满足原合同。
原布局开缓存相对关闭，18 项任务用时之和下降 10.20%，但逐题配对降幅中位只有 0.43%，收益主要来自两道纠错题。
证据前置虽然提高缓存复用，却增加纠错与输出，总用时更长，未采用。见 [推理配置对照](results/inference-i2-20261006/README.md)。

vLLM 经真实 HTTP / PostgreSQL 消费，通过 10 项服务检查，覆盖过载、断连、未知结果与强杀恢复；
请求合同已改变，不继承上面的提速。这是现成 vLLM 集成与可靠请求工程，不是自研内核或集群调度。
见 [可选推理服务](results/inference-i3-20261007/README.md) 与 [运行说明](inference-backend.md)。

## 预测后的持续评价

固定模型先预测，实况按模拟到达时间进入逐起报、逐时距的残差账本，HTTP 与 CLI 给出持续性主用与候选影子的滚动比较。
历史回放完成 144 次起报、864 组成对时距记录，真实 PostgreSQL、独立 CLI 与 TCP 进程重启后可续跑。
见 [延迟实况监测](results/wind-monitor-w1-20261005/README.md)。

缺测案例把窗口内成对样本、待到达、到期缺测、无效输入和预测失败与 MAE 并列：受控补齐窗口外实况后，
累计成对数 22→23，但窗口仍是 11/12、MAE 不变；补齐窗口内实况才达到 12/12。
见 [缺测与样本支持](results/wind-monitor-w2-20261006/README.md)。20 分钟到达延迟为模拟，缺测为测试注入。
