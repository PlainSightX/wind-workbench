# 查询规划微调：Qwen3-8B LoRA 在组合规划首答上的对照

2026-10-16～17 完成。只测结果助手的「查询规划」一步：给定问题与证据，模型输出
`requests` JSON（每个子请求选择 values / compare / sort / coverage / time / stage 等操作，
或声明真实缺口）。随后由程序执行并校验。本页公开本轮的数据、逐题结果与训练/评测脚本；没有改动产品默认模型。
同一适配器随后接入服务回答链路（校验、修复、HTTP），端到端 233/300 = 77.7%，原始 8B 为 57/300 = 19.0%，
见[接入服务结果](../sft-service-integration-20261017/README.md)；规划接口源码见
`src/power_forecast_service/assistant/program.py`。

## 结果

评分复用项目原有的自动检查：真实消费者执行、义务覆盖、范围与显式顺序都必须正确（“通过”）。
“严格”另要求没有任何待复核差异，例如请求分组或缺口措辞与标准计划不同。

| 模型 | 300 题 通过 | 300 题 严格 | dev32 通过 | 300 题耗时 |
|---|---:|---:|---:|---:|
| Qwen3-8B 原始 | 18.3% | 10.0% | 12/32 | 1015 s |
| Qwen3-32B 原始 | 33.7% | 24.0% | 14/32 | 2883 s |
| 此前 32B LoRA（286 条监督） | 31.3% | 20.3% | 7/32 | 2645 s |
| DeepSeek-Flash（服务默认 `deepseek-chat`） | 41.3% | 31.7% | 18/32 | 28 s（API 并发） |
| **Qwen3-8B + LoRA（本轮）** | **77.3%**（95% CI 72–82） | **70.7%** | **29/32** | **589 s** |

- dev32 是此前事前写好的组合开发集，题型与措辞不来自本轮数据生成器。
- 同题配对 McNemar：本轮 vs DeepSeek-Flash，test300 112:4，dev32 11:0（p=0.001）。
- 三子问题组合由 3/128 提升到 76/128；训练中未出现的子问题配对 51/75。
- 本地模型在单张 RTX PRO 6000 上用 vLLM 批量运行；每题约 2.3 万 token 证据，耗时以 prefill 为主。
- 逐题结果见 `per-question.json`，汇总见 `summary.json`，全部训练/测试问题与标准计划见
  `train-questions.json`、`test-questions.json`。

## 做法

- **数据**：18 种原子义务（读数、比较、合取、排序、改善率、BIAS 判断、覆盖计数、评价期间、
  起报时间、延迟规则、开发/采用/正式边界、四类真实缺口）按 1～3 个组合成问题。
  标准计划按问题中的出现顺序排列，每条都经过真实消费者执行与自动检查自检。
- **切分**：测试只用训练中没有的连接模板与原子问法；约 15% 的原子配对只出现在测试中。
- **训练**：Qwen3-8B，LoRA r16/α32，全部线性层，lr 1e-4 余弦，2 epoch，批 8，
  只在 completion 上计算损失；单卡约 4 小时。
- **评测**：vLLM 0.11.2 贪心解码 + JSON schema 约束；比例附 Wilson 区间，模型间同题配对检验。

## 两个工程问题

- **注意力内核**：transformers 默认给 SDPA 传显式 causal mask，23k token 的反向退回内存高效内核。
  单样本无 padding 时改用 `is_causal=True`，走 flash 路径，前反向耗时 29 s → 9 s。
- **字段顺序**：训练目标以 `sort_keys` 序列化（`presentation` 在前），约束解码按 schema 原序生成
  （`presentation` 在后），模型因此系统性漏写 `presentation`。推理时把 schema properties 按字母序排列，
  同一适配器 49.3% → 77.3%，无需重训。原始 8B 用字母序反而降到 4.3%，所以表中每个基线都报告它更好的顺序。

## 局限

- test300 与训练出自同一生成器（同一套原子与四个证据来源），模板与部分组合留出，但不是独立来源泛化。
  dev32 更独立，但只有 32 题。
- 旧问法回归面板 current40 上与此前 32B LoRA 持平（28/40 对 29/40）。
- 自动检查在 dev32 上比此前的逐题复核更严；此前 32B LoRA 的原始输出在逐题复核下为 21/32。
- 本页只测首答规划质量，不含 HTTP、修复调用与编译器路由；性能数字不代表服务端到端延迟。
  服务链路的端到端结果见[接入服务结果](../sft-service-integration-20261017/README.md)。
