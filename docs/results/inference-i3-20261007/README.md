# I3：可选推理服务与可靠请求边界

## 本轮结果

同一Qwen3-14B-FP8、vLLM、原布局与APC候选已通过真实HTTP，被独立FastAPI与
PostgreSQL消费。`service-v4`退出码0，10项预定服务检查通过；五份可见完整交付
经父会话逐份复核，事实、引用和阶段关系通过，非外部盲审。原始回答、请求、
日志、连接资料和完整审计保存在私有工作包，不进入这份公开精选报告。

本轮不改默认provider/布局、普通18000服务、预测训练和I2历史结果。新迁移只
用于自有随机库，原业务库没有运行0008。可选后端的公开配置与复现仍由I4整理。

## 实际路径

```text
POST /assistant/answers + X-Request-ID
  -> 进程内容量准入
  -> PG登记请求身份、输入指纹、截止时间
  -> 当前对象查询 + 当前文档检索 + 本次JSON Schema
  -> PG提交call_id及dispatching状态
  -> HTTP/SSE消费vLLM，完整性检查，最多一次业务纠错
  -> 事实/引用/阶段校验 + 审计hash + 请求最终状态
GET /assistant/requests/{id} -> 原身份状态（不返回保存的答案）
```

可选适配器只接受运维配置的loopback地址；不让问题正文提供服务器地址。传输
不完整、超时或未知结果不触发业务纠错；业务校验失败在原两调用预算内处理。
PG只保存身份、调用状态与结果hash，未新增问答原文存储。

## 验收证据

| 工作面 | 真实观测 | 证明范围 |
|---|---|---|
| 顺序切换 | 两个开发对象及一个最终对象成功交付 | 本次对象绑定，不是任意仓库/问题泛化 |
| 并发切换 | 容量2时两对象分别返回各自指标 | 当前两请求隔离，不是全局并发容量 |
| 越界 | 指向未选择对象时调用数0 | 工具层范围拒绝 |
| 断开与过载 | 真实客户端超时后容量仍占用，另一请求429 | 断开不提前释放本地槽位 |
| 重复请求 | 已完成与未知请求同ID再提交均409 | 此身份不再自动发送，不是答案重放 |
| 交付丢失 | 故障代理先观察真实模型stop/usage，再去掉SSE结束标志 | 远端执行过、本地无法确认时标记未知 |
| 进程中断 | 模型完成后暂扣交付，强杀API，重启查询原身份 | 到期可见unknown，代理未收到新增调用 |
| PostgreSQL | 随机库迁移/check、20项集成检查 | 真实PG，非SQLite或mock数据库 |
| 清理 | 自有随机库删除，API/隧道结束，登记端口无监听 | 不杀其他进程，不重启普通服务 |
| 数据不变 | 原ImportedRun/ImportedArtifact行hash前后一致 | 仅这两张导入表，不扩大为全库所有数据 |

最新离线检查：342项助手/基线/优化/配对测量器回归，6项服务验证器单测；真实PG
检查20项。均退出码0，diff检查通过。离线测试数不代替真实服务和语义证据。

## 语义复核与失败整改

五份可见HTTP交付覆盖顺序三对象和并发两对象。两个开发对象的MAE、负改善率
分别正确，未串用。最终问题明确区分开发改善、项目事前3%采用门、未采用且
默认持久性、2015最终留出改善；没有用最终结果追认开发选择。引用版本/连续
原文与当前文档一致。断连请求只核对完成状态/审计，不补造不可见正文的结论。

失败不是被成功批次覆盖：

- v1：验证器把公开引用的`revision`当成内部`source_sha256`，修字段并补回归。
- v2：Windows快速复用同一端口失败，改为在登记范围内为独立进程分配不同端口。
- v2另有真实语义错：模型把置信区间当采用门；数值/版本正确不足以验收这层关系。
- v3技术检查通过后仍保留待审标记；v4作为最终本轮交付单独绑定，未拼接成功答案。

整改保留完整输入，但按问题区分“采用门事实”和“被请求的区间事实”，并对明确
混淆增加局部检查；合法的区间问题仍允许区间，不宣称通用自然语言语义判定。
正文仍有重复字段标签，标题“2014三季度汇总”有歧义，表达尚不精练。

## 限制与后续

I3请求合同已变化，不将[I2](../inference-i2-20261006/README.md)的10.20%整组
用时下降直接宣称为服务提速。这里没有新任务泛化、生产SLA、答案持久重放、
跨进程全局限流、远端exactly-once或自研KV/解码内核结论。

当前unknown策略优先避免重复副作用，不能自动取回丢失答案；要重做任务需由人
了解原状态后使用新身份。容量目前是单API进程内上限，不冒充集群调度。

下一步I4整理安全公开配置/迁移/复现、导出与CI覆盖以及可核验就业表述。不要
把本轮完成包装成整个AI Infra阶段收口；不为增加技术名词再引入未经验证的栈。
