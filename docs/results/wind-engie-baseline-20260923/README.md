# ENGIE四机组滚动预测：基线结果

日期：2026-09-23。状态：数据准入、开发对照与独立进程重放已完成。
**本轮实现了真实场站公开数据上的可复查基线，没有取得相对持久性的主MAE提升。**
2015年没有参与拟合、调参或评分；旧Q1模型、成绩、API和队列未变更。

## 1. 这轮交付了什么

每十分钟起报一次，使用模拟可得的四台机组历史，输出未来10至60分钟六点功率，
包含各机组和固定四台合计。准入、窗口、训练选择、完整输出、评分和保存模型的
重新加载都已实际运行。不是只下载数据或提出另一份方案，也不是已经上线的实时预测。

本轮使用ENGIE公开原始SCADA，经OpenOA固定版本获取；数据许可为Etalab Open
Licence 2.0，归属ENGIE。来源地址、版本、ZIP/CSV的SHA及质量统计见
[数据准入](admission.json)。原始ZIP保留在本地非Git工件区，没有把数据复制进仓库。

## 2. 数据合同与真实问题

完整文件有420480行，包含2014-2015年四台机组的十分钟记录。每台存在12个重复
UTC键和12个缺失键；重复键的值相互冲突，集中在春季夏令时切换，秋季有对应断档。
源字符串的UTC偏移已经被正确解析，不能通过重新猜时区来虚构正确观测。

处理规则是在冲突键上整组判为不可用，对缺测或非有限输入拒绝相应窗口。没有取
第一行、平均重复值、插值、补零或把四台合计偷偷改成三台。低出力与负功率保留。
这是一项真实的数据准入问题，不是人为造出来的模型失败。

| 合同项 | 本轮实际使用 |
|---|---|
| 机组 | R80711、R80721、R80736、R80790，集合固定 |
| 信息时间 | 起报t只用标签不晚于t-20分钟的观测；20分钟是模拟假设 |
| 输入 | 每台连续12条历史，每条功率、风速、风向sin/cos、温度，共60维 |
| 目标 | t+10、20、30、40、50、60分钟的原始kW，不作非负裁剪 |
| 开发 | 2014年Q2/Q3/Q4三个外层窗，使用扩展的过去历史训练 |
| 内层 | 过去最后28天选参数，训练标签加20分钟可得延迟必须严格早于下一段 |
| 保留期 | 2015年只检查键/缺数/非有限值等质量，不分析功率分布或模型效果 |
| 排名 | 完整覆盖预定可评分集合，三个季度等权的四台合计六时距raw MAE |

四台SCADA之和不是并网净送出或排除限电后的可用功率。真实到达时间、十分钟平均
区间端点与容量单位注释仍有限制；因此不报告真实SLA、容量归一化误差或经济收益。
未使用未来再分析天气和包内的合成meter/损失标签。

## 3. 覆盖不是只算成功样本

| 外层窗 | 计划起报 | 合法输入/各模型实际输出 | 完整可评分 | 可评分占计划 |
|---|---:|---:|---:|---:|
| 2014-Q2 | 13104 | 12932 | 12880 | 98.291% |
| 2014-Q3 | 13248 | 13248 | 13248 | 100.000% |
| 2014-Q4 | 13248 | 13045 | 12991 | 98.060% |
| 合计 | 39600 | 39225 | 39119 | 98.785% |

三个季度均超过事前80%数据准入线。375次输入不合法；另有106次正常产生了预测，
但不能完整评分，其中Q4最后六次的目标越过2015边界。未来标签是否齐全没有决定
当时是否预测。三个模型的合法输入输出覆盖均为100%，占全部计划起报的99.053%。
这不是墙钟按时交付率。39119个起报窗口高度重叠，不能当作39119个独立试验。

## 4. 实际模型结果

| 四台合计raw MAE，kW | Persistence | Ridge | LightGBM |
|---|---:|---:|---:|
| Q2 | 431.068 | 460.269 | 475.291 |
| Q3 | 338.278 | 357.741 | 365.566 |
| Q4 | 398.606 | 415.666 | 415.304 |
| 等季度均值 | **389.317** | 411.225 | 418.720 |
| 相对基线MAE变化 | 参照 | 恶化5.63% | 恶化7.55% |
| 等季度RMSE，kW | 652.989 | **628.283** | 645.504 |

两个学习模型在全部三个季度、每个时距的MAE都弱于持久性，并非只有一个差季度。
Ridge的RMSE改善3.78%，LightGBM改善1.15%；但主指标事前定为MAE，不能事后换成
RMSE宣布获胜。当前推荐的ENGIE开发基线是持久性，不替换旧Q1服务中的Ridge。

Ridge候选alpha为1/10/100，内层按场站六时距MAE选择，三个季度均选100；
StandardScaler只在相应训练段拟合。LightGBM每机组/时距单独拟合，最多400棵树，
内层按各机组/时距MAE早停，再用固定轮数在全部合格历史重拟合。
二者选型粒度不同，不能将差异全部归于模型架构。完整参数在[冻结协议](protocol.json)。

### 哪些地方学到了，哪些地方反而损害了

以下为每个季度分别计算后等权汇总的组内MAE变化，不是可部署的分流规则：

| 事后诊断组 | Ridge相对持久性 | LightGBM相对持久性 |
|---|---:|---:|
| 真实变化较大 | 改善11.15% | 改善10.03% |
| 真实变化较小 | 恶化23.12% | 恶化25.79% |
| 实际出力较低 | 恶化90.15% | 恶化76.55% |

分组阈值来自过去训练，但组别仍使用未来实际标签判断；不能在起报时直接根据它们
选模型。低实际出力组可与变化组重叠。上述模式和RMSE说明模型不是完全没学到
东西，而是当前取舍不符合主目标；尚不能排除信息不足、季节变化等其他原因。

## 6. 成本、复核与执行修复

三季度合计192次底层估计器拟合：Ridge48次、LightGBM144次，持久性不训练。
九个季度/模型工件不等于九次拟合。实测累计拟合71.793秒，其中Ridge2.745秒、
LightGBM69.048秒；整批预测合计约0.021/0.058/1.203秒。均为本机CPU批处理，
不是单请求P99、队列时效或生产成本比较，没有云/API费用。

26项定向测试通过；独立进程从原ZIP重建样本和各分母，复算raw指标和分组，禁止
所有fit方法后重新加载九包，逐条预测与保存结果最大差均为0，验收拟合次数为0。
正常案例、缺机组案例、三个季度/三类模型完整性、冻结身份和环境均已核对。
[验收结果](verification.json)仅证明此开发协议，不代表2015效果或服务接入。

首次执行在拟合前被协议检查拒绝：tuple经JSON变成list，导致未改变的合同被误判。
修复序列化并增加roundtrip测试后，在没有任何模型结果时重新冻结；旧协议保存在
[拟合前拒绝记录](prefit-rejected-protocol.json)。没有删负分数重跑。
恢复路径也明确拒绝未完成的孤立工件，完成窗口只核hash并保留，不覆盖或重新拟合。
验收审阅补了缺整季度和损坏展示示例的拒绝检查，仅修改未冻结的验收器，没有改
任何已评分的训练代码。现有Timedelta弃用警告保留，不为消除警告临时换依赖。

普通结果复查只运行以下命令，不训练、不启动服务：

```powershell
.\.venv\Scripts\python.exe tools/diagnostics/verify_engie_baseline.py --result docs/results/wind-engie-baseline-20260923/baseline.json
```

复用准入记录所指向的固定ZIP；已有完成结果不允许直接再次`run`覆盖。
源码/小型回执在Git，原ZIP、权重和逐点NPZ在本机工件区；Git不是这些工件的备份。

## 7. 具体下一轮与阶段位置

建议只检验一个假设：**把LightGBM的平方误差训练目标改成L1，能否减少普通样本
的过度修正，从而改善主MAE？** 现行配置的`metric=l1`用于监控/早停，训练
`objective=regression`没有因此改变。这个差异是可定位的改动，不是换名字或扩大搜索。

下一轮先冻结比较：同数据、特征、季度、种子、树预算和内层选择方式，只改变损失，
并与本轮LightGBM和持久性比较。主MAE之外同时看逐季/逐时距、RMSE、大变化组和
覆盖，避免用尾部显著退化换一个平均好看数；具体通过门槛要在候选拟合前确定。
如果不能改善，停止这一假设，不靠追加种子、删时段或打开2015找收益。

这只是待批准的下一轮，不是已找到唯一根因或承诺一定改善。后续仍需新合同的同包
服务交付、正常/故障交付对照及冻结后的2015评价。阶段C和用户触发结对保留。
本轮的真实增量是数据问题处理、无前视的可比输出和明确的失败模式；新的预测提升
与就业项目的完整阶段目标尚未完成，不用测试数量代替它们。
