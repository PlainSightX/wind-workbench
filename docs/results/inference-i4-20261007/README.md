# I4：可选推理的公开复现候选

## 交付与实际消费

提供[显式宿主入口](../../../tools/dev/serve_inference.py)和[运行说明](../../inference-backend.md)，
先只读检查有效PG迁移head/请求表、模型目录中的服务名/上下文及独立端口，再选择启动。
不自动迁移旧库、不默默回退provider、不把容器loopback当宿主隧道。

公开候选为279个精选文件，四个测量模块与产品测试的依赖链闭合。实际消费者从
候选自身src加载，不从维护仓补模块；未安装新依赖。候选全unit为581通过、4跳过，
后者是Windows缺sh的POSIX初始化组；另24项真实PG检查全部通过。

PG组验证当前迁移、旧head拒绝、缺请求表拒绝、只读模型目录，以及新CLI实际启动
的TCP健康/请求状态接口，结束自己的API并释放端口。模型目录在这些测试中注入，
**不算真实GPU质量或性能**；随机测试库由夹具创建和回收，不升级普通业务库。
公开导航另按导出目标解析，I2长维护记录仅用精选摘要交付，不把内部历史整段公开。

## 检查发现的真实回归

首次候选全unit未通过：I3新增状态路由遗漏了OpenAPI清单更新，且API定义导入
经requests/storage/pgvector提前加载了NumPy，破坏原轻量边界。修复后将相关导入
推迟至实际journal请求阶段，保留无凭据/无联网/无数值库的隔离导入断言，再重新
导出验证；不是删断言或只跑新增测试。旧失败收据与候选差异保持私有可恢复。
