同一Qwen3-14B-FP8、vLLM0.11.2/XGrammar0.1.25，原六个已见开发问题，完整输入
22,206至26,329token；原数值/引用/阶段/时间rubric，最多两次调用/75秒预算不变。
合格候选先在两个冻结批次中分别通过6/6；不是首稿全对、外部盲审或未见题泛化。

## 三轮四格

顺序为 `A B D C`、`C D B A`、`B A C D`，同轮题序一致并轮换。每格先完成
原布局六题预热，再实际清缓存，核对首个正式调用零命中。预热72项不进入成绩。

| 配置 | 布局 / APC | 合同与语义通过 | 调用 / 输出token | 18任务用时之和秒 |
|---|---|---:|---:|---:|
| A | 原布局 / 关闭 | 18/18 | 24 / 4842 | 276.893 |
| B | 原布局 / 开启 | 18/18 | 24 / 4842 | 248.659 |
| C | 完整证据前置 / 关闭 | 18/18 | 30 / 7296 | 390.423 |
| D | 完整证据前置 / 开启 | 18/18 | 30 / 7296 | 294.902 |

共72项正式任务、12个清缓存批次，12种不同完整交付逐份绑定父会话语义审阅。
相同完整交付才复用结论；72项不是72个独立问题，机器通过也不代替语义复核。

## 采用与不采用

A/B的18对任务中原始调用序列逐字相同，调用数和输出token相同。采用B，整组
任务用时之和下降10.20%，但逐题配对降幅中位仅0.43%，收益主要来自两题纠错。
不同问题首调用缓存复用约2.26%，同题纠错命中另计；不能称多数问题显著提速。

D相对C整组用时下降24.47%，不同问题首调用复用约67.51%，说明共享证据前置
有prefill价值；但D相对B多25%调用、50.68%输出token、18.60%完整任务用时。
两题增加纠错，附加表达仍有空数字瑕疵，因此本轮不采用D，不否定未来负载下的价值。

APC由现成vLLM实现，作用于prefill，不是自研KV内核或decode优化。任务用时包含
业务纠错，不含切换/预热，不是云账单、生产吞吐或HTTP/PG端到端时延。

模型revision为 `9a283b4a5efbc09ce247e0ae5b02b744739e525a`；固定temperature0.7、
seed42、top_p0.8、top_k20、min_p0、thinking关闭、32768上下文和1700输出上限。
